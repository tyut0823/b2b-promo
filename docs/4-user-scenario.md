## 1. 개요

본 문서는 `3-PRD.md`의 기능 요구사항, 비즈니스 규칙(4.5), 예외 케이스(4.6)를 근거로 b2b-promo의 핵심 사용자 시나리오를 정리한다. 액터는 관리자(Admin)와 거래처 담당자(Buyer) 두 역할만 다루며, PRD 8절 제외 범위(승인 워크플로우, 재고/수량 관리, 검색 등)에 해당하는 기능은 다루지 않는다.

## 2. 관리자 시나리오

### 2.1 샘플 등록/수정

- **액터**: 관리자
- **사전 조건**: 관리자로 로그인된 상태
- **기본 흐름**
  1. 관리자가 샘플 관리 화면에 진입한다.
  2. 샘플명, 설명, 이미지, 신청 시작일/종료일을 입력하고 등록을 요청한다.
  3. 시스템이 샘플을 저장하고 목록에 반영한다.
  4. 기존 샘플을 수정할 경우, 샘플을 선택해 동일 항목을 수정 후 저장한다.
- **예외/대안 흐름**
  - 로그인하지 않은 상태로 접근 시: 로그인 화면으로 이동한다(4.6 로그인하지 않은 접근).

### 2.2 신청 현황 조회

- **액터**: 관리자
- **사전 조건**: 관리자로 로그인된 상태, 등록된 샘플이 존재함
- **기본 흐름**
  1. 관리자가 특정 샘플을 선택한다.
  2. 시스템이 해당 샘플을 신청한 거래처 목록과 각 신청의 상태(신청/취소)를 보여준다.
- **예외/대안 흐름**
  - 로그인하지 않은 상태로 접근 시: 로그인 화면으로 이동한다.

## 3. 거래처 담당자 시나리오

### 3.1 회원가입/로그인

- **액터**: 거래처 담당자
- **사전 조건**: 없음(신규 사용자)
- **기본 흐름**
  1. 거래처 담당자가 이메일, 비밀번호, 이름, 소속 거래처명을 입력해 자가 회원가입한다.
  2. 가입한 이메일/비밀번호로 로그인한다.
  3. 로그인 성공 시 샘플 목록 화면으로 이동한다.
  4. (부가 기능) 그날 처음 로그인한 것이면 일일 신청 가능 개수 룰렛이 뜬다. 담당자가 STOP을 눌러 회전을 멈추면 1~3 중 하나의 결과가 정해지고, 그 개수가 그날의 신청 가능 횟수가 된다(같은 날 재로그인해도 재추첨하지 않음). 화면 우측 상단에 남은 개수가 계속 표시되며, 클릭하면 오늘 뽑은 결과를 다시 볼 수 있다.

### 3.2 샘플 목록/상세 조회

- **액터**: 거래처 담당자
- **사전 조건**: 로그인된 상태
- **기본 흐름**
  1. 거래처 담당자가 샘플 목록 화면에 진입한다.
  2. 시스템이 신청 예정(시작일 이전) 또는 신청 가능(신청 기간 내)한 샘플 목록을 보여준다.
  3. 특정 샘플을 선택하면 상세 정보(설명, 이미지, 신청 기간)를 조회한다.
- **예외/대안 흐름**
  - 로그인하지 않은 상태로 접근 시: 로그인 화면으로 이동한다.

### 3.3 샘플 신청

- **액터**: 거래처 담당자
- **사전 조건**: 로그인된 상태, 신청 기간(시작일~종료일) 내인 샘플이 존재함
- **기본 흐름**
  1. 거래처 담당자가 샘플 상세 화면에서 신청 버튼을 누른다.
  2. 시스템이 해당 (샘플, 거래처) 조합에 대한 신청 레코드를 새로 생성하고 상태를 '신청'으로 저장한다.
  3. 신청 완료를 안내한다.
- **예외/대안 흐름**
  - **중복 신청**: 이미 '신청' 상태인 동일 샘플에 다시 신청을 시도하면 새 레코드를 만들지 않고 "이미 신청한 샘플입니다."를 안내한다.
  - **신청 시작 전**: 신청 시작일 이전에는 신청 버튼을 통한 신규 신청을 허용하지 않는다(조회만 가능).
  - **신청 기간 종료 후**: 신청 종료일 다음 날부터는 신규 신청을 허용하지 않는다.
  - **(부가 기능) 일일 신청 가능 개수 초과**: 그날 룰렛으로 뽑은 개수만큼 이미 신청했다면, 화면에서 신청 버튼이 숨겨지거나 비활성화되어 추가 신청을 시도할 수 없다(프론트엔드 제한, 서버 검증 없음).

### 3.4 신청 취소 및 재신청

- **액터**: 거래처 담당자
- **사전 조건**: 로그인된 상태, 해당 샘플에 대해 '신청' 상태인 신청 레코드가 존재함
- **기본 흐름**
  1. 거래처 담당자가 내 신청 내역 또는 샘플 상세에서 취소를 요청한다.
  2. 시스템이 기존 신청 레코드의 상태를 '신청 → 취소'로 변경한다(레코드 삭제/신규 생성 없음).
  3. 신청 기간 내에 동일 샘플을 다시 신청하면, 시스템이 기존 레코드의 상태를 '취소 → 신청'으로 되돌린다(새 레코드 생성 없음).
- **예외/대안 흐름**
  - **신청 기간 종료 후 재신청**: 취소 이후 신청 종료일 다음 날부터는 재신청(취소→신청 전환)을 허용하지 않는다.

### 3.5 내 신청 내역 조회

- **액터**: 거래처 담당자
- **사전 조건**: 로그인된 상태
- **기본 흐름**
  1. 거래처 담당자가 내 신청 내역 화면에 진입한다.
  2. 시스템이 본인이 신청한 샘플 목록과 각 신청의 상태(신청/취소)를 보여준다.
- **예외/대안 흐름**
  - 로그인하지 않은 상태로 접근 시: 로그인 화면으로 이동한다.

## 4. 공통 시나리오

### 4.1 마이페이지(내 정보 수정/비밀번호 변경)

- **액터**: 관리자, 거래처 담당자
- **사전 조건**: 로그인된 상태
- **기본 흐름**
  1. 사용자가 마이페이지에 진입해 내 정보(이름, 소속 거래처명 등)를 조회한다.
  2. 정보를 수정하고 저장을 요청하면 시스템이 반영한다.
  3. 비밀번호 변경을 요청하면 새 비밀번호를 해시로 저장한다.
- **예외/대안 흐름**
  - 로그인하지 않은 상태로 접근 시: 로그인 화면으로 이동한다.

### 4.2 로그아웃

- **액터**: 관리자, 거래처 담당자
- **사전 조건**: 로그인된 상태
- **기본 흐름**
  1. 사용자가 네비게이션의 로그아웃 버튼을 누른다.
  2. 시스템이 인증 상태(토큰)를 초기화하고 로그인 화면으로 이동시킨다.

### 4.3 미인증 접근 처리

- **액터**: 관리자, 거래처 담당자(비로그인 상태의 모든 사용자 포함)
- **사전 조건**: 없음(로그인하지 않은 상태)
- **기본 흐름**
  1. 인증되지 않은 사용자가 로그인이 필요한 화면/기능에 접근을 시도한다.
  2. 시스템이 요청을 거부하고 로그인 화면으로 이동시킨다.
