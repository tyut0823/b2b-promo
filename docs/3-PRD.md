## 1. 개요

b2b-promo는 식자재 유통사의 관리자가 등록한 상품 샘플을, 거래처(외식업체·급식업체 등) 담당자가 조회하고 직접 신청할 수 있도록 하는 B2B 샘플 신청 웹 애플리케이션이다.

기존에는 신청 가능한 샘플 정보가 영업 담당자의 개별 안내, 전화, 카톡 등으로 흩어져 전달되어 거래처가 신청 기회를 놓치기 쉬웠다. 본 앱은 샘플 등록·조회·신청·신청 현황 확인을 한 곳으로 모아 이 문제를 해결한다.

본 문서는 교육용 바이브코딩 실습 MVP의 제품 요구사항을 정의하며, `1-domain-definition.md`에서 정의한 도메인(액터, 엔티티, 유스케이스, 예외 케이스, 비즈니스 규칙, MVP 범위)을 기능 요구사항의 근거로 삼는다.

## 2. 목표 및 성공 지표

- 목표 사용자: 1,000개 이상의 거래처가 등록하여 사용
- 비즈니스 목표: 3,000개 이상의 거래처가 프로모션(샘플 신청) 기능을 이용

## 3. 대상 사용자 (액터)

| 역할 | 설명 |
|---|---|
| 관리자(Admin) | 유통사 소속. 샘플을 등록·수정하고 거래처별 신청 현황을 조회함 |
| 거래처 담당자(Buyer) | 외식업체·급식업체 등 거래처 소속. 자가 회원가입 후 샘플을 조회·신청·취소함 |

두 역할 모두 로그인 후에만 기능을 이용할 수 있으며, 마이페이지(내 정보 조회/수정, 비밀번호 변경)를 공통으로 이용한다.

## 4. 기능 요구사항

### 4.1 관리자 기능

- **샘플 등록/수정**: 샘플명, 설명, 이미지, 신청 시작일/종료일을 입력해 샘플을 등록하거나 기존 샘플 정보를 수정한다.
- **신청 현황 조회**: 특정 샘플을 선택해 해당 샘플을 신청한 거래처 목록과 상태(신청/취소)를 조회한다.

### 4.2 거래처 담당자 기능

- **회원가입/로그인**: 자가 회원가입 후 로그인한다.
- **샘플 목록/상세 조회**: 신청 예정 또는 신청 가능한 샘플 목록과 각 샘플의 상세 정보를 조회한다.
- **샘플 신청**: 신청 가능한 샘플에 대해 신청 버튼을 눌러 신청을 등록한다.
- **내 신청 내역 조회**: 자신이 신청한 샘플 목록과 각 신청의 상태(신청/취소)를 조회한다.
- **신청 취소**: 신청 상태인 샘플을 취소한다(신청 기간 내라면 이후 재신청 가능).

### 4.3 공통 기능

- **마이페이지**: 관리자·거래처 담당자 모두 내 정보를 조회/수정하고 비밀번호를 변경한다.

### 4.4 핵심 엔티티

- **사용자(User)**: 계정 유형(관리자/거래처 담당자), 이메일(로그인 ID), 비밀번호, 이름, 소속 거래처명. 거래처 담당자는 자가 회원가입으로 생성됨.
- **샘플(Sample)**: 샘플명, 설명, 이미지, 신청 시작일, 신청 종료일. 신청 기간(시작일~종료일, 양일 포함) 기준으로 신청 가능 여부가 결정되며, 예정/진행중/종료 상태는 별도 저장 필드 없이 날짜 비교로 자동 판단한다.
- **신청(Application)**: 특정 샘플에 대한 특정 거래처 담당자의 신청 1건. 상태는 신청(APPLIED)/취소(CANCELLED). (샘플, 거래처) 조합당 신청 레코드는 유일하게 하나만 존재한다.

### 4.5 비즈니스 규칙

- "샘플 신청"은 (샘플, 거래처) 조합당 유일하다. 동일 조합에 대해 신청 레코드는 항상 하나만 존재한다.
- 이미 '신청' 상태인 (샘플, 거래처) 조합에 대한 재신청 요청은 새 레코드를 만들지 않고 "이미 신청한 샘플입니다."를 안내한다.
- 신청 취소는 레코드를 삭제하거나 새 레코드를 만들지 않고, 기존 신청 레코드의 상태를 '신청 → 취소'로 변경한다.
- 취소한 샘플을 다시 신청하는 경우에도 새 레코드를 만들지 않고, 기존 신청 레코드의 상태를 '취소 → 신청'으로 되돌린다.
- 신청 시작일 이전에는 신규 신청을 허용하지 않는다(조회만 가능).
- 신청 종료일 당일까지는 신청·재신청이 가능하며, 종료일 다음 날부터는 신규 신청과 재신청(취소→신청 전환) 모두 허용하지 않는다.
- 모든 기능은 로그인(인증)한 사용자만 이용할 수 있다.

### 4.6 예외 케이스

- **중복 신청**: 동일 거래처가 이미 '신청' 상태인 동일 샘플에 다시 신청을 시도하면 신규 신청을 생성하지 않고 "이미 신청한 샘플입니다."를 안내한다.
- **신청 시작 전 신청 시도**: 신청 시작일 전(신청 예정 상태)에는 목록·상세 조회는 가능하나 신청은 허용하지 않는다.
- **신청 기간 종료 후 신청/재신청**: 신청 종료일 다음 날부터는(종료일 당일까지는 신청 가능) 신규 신청 및 취소 후 재신청을 모두 허용하지 않는다.
- **로그인하지 않은 접근**: 인증되지 않은 사용자는 어떤 기능도 이용할 수 없으며 로그인 화면으로 이동한다.

## 5. 비기능 요구사항

- 모바일/데스크탑 대응 반응형 웹 UI를 반드시 적용한다(모바일 전용 앱/네이티브 앱 없음).
- 접근성은 이번 MVP에서 별도로 고려하지 않는다.

### 5.1 보안

- 비밀번호는 해시로 저장한다(평문 저장 금지).
- 인증은 JWT 기반으로 access token과 refresh token을 모두 사용한다.

## 6. 기술 스택 및 아키텍처 제약

- 프론트엔드: React 19, 전역 상태관리는 Zustand, 서버 상태(백엔드 통신)는 TanStack Query 사용
- 백엔드: Node.js + Express, DB 접근은 pg 라이브러리 사용
- 데이터베이스: PostgreSQL 17

## 7. 프로젝트 일정 및 리소스

- 일정: 3일 내 핵심 기능 완성
- 팀 구성: 1인 개발
- 예산: 1인 개발 규모에 준함

## 8. MVP 범위

**포함**
- 관리자의 샘플 등록·수정 및 신청 현황 조회
- 거래처 담당자의 회원가입/로그인
- 거래처 담당자의 샘플 조회·신청·취소·신청 내역 조회
- 관리자·거래처 담당자 공통 마이페이지(내 정보 조회/수정, 비밀번호 변경)
- 모바일/데스크탑 대응 반응형 UI

**제외**
- 실제 상품 주문/결제/정산
- 배송 관리
- 실시간 재고 연동
- 샘플 재고 및 신청 가능 수량 관리
- 신청 승인 워크플로우
- 거래처 등급별 신청 조건 및 차등가
- 포인트/리워드
- 검색 기능
- 외부 시스템 연동

## 9. 용어집

| 용어 | 설명 |
|---|---|
| 샘플(Sample) | 거래처에 제공 가능한 상품 샘플. 신청 기간이 있음 |
| 신청(Application) | 거래처 담당자가 특정 샘플에 대해 등록한 신청 건 |
| 신청 상태 | 신청(APPLIED) 또는 취소(CANCELLED) |
| 거래처(Buyer) | 식자재를 구매하는 외식업체·급식업체 등 B2B 고객사 |
| 신청 기간 | 샘플의 신청 시작일부터 신청 종료일까지의 기간 |
