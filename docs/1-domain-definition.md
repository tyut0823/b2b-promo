## 1. 개요

b2b-promo는 식자재 유통사의 관리자가 등록한 상품 샘플을, 거래처(외식업체·급식업체 등) 담당자가 조회하고 직접 신청할 수 있도록 하는 B2B 샘플 신청 웹 애플리케이션이다.

기존에는 신청 가능한 샘플 정보가 영업 담당자의 개별 안내, 전화, 카톡 등으로 흩어져 전달되어 거래처가 신청 기회를 놓치기 쉬웠다. 이 앱은 샘플 등록·조회·신청·신청 현황 확인을 한 곳으로 모아 이 문제를 해결한다.

본 문서는 교육용 바이브코딩 실습 MVP의 도메인을 정의하며, 구현에 반드시 필요한 최소한의 엔티티와 규칙만 다룬다.

## 2. 역할(Actor)

| 역할 | 설명 |
|---|---|
| 관리자(Admin) | 유통사 소속. 샘플을 등록·수정하고 거래처별 신청 현황을 조회함 |
| 거래처 담당자(Buyer) | 외식업체·급식업체 등 거래처 소속. 자가 회원가입 후 샘플을 조회·신청·취소함 |

두 역할 모두 로그인 후에만 기능을 이용할 수 있으며, 마이페이지(내 정보 조회/수정, 비밀번호 변경)를 공통으로 이용한다.

## 3. 핵심 엔티티

### 사용자 (User)
- 계정 유형(관리자/거래처 담당자), 이메일(로그인 ID), 비밀번호, 이름, 소속 거래처명 등 기본 정보를 가짐
- 거래처 담당자는 자가 회원가입으로 생성됨

### 샘플 (Sample)
- 샘플명, 상품 설명, 이미지, 신청 시작일, 신청 종료일을 가짐
- 신청 기간(시작일~종료일, 양일 포함)을 기준으로 신청 가능 여부가 결정됨(예정/진행중/종료는 날짜 비교로 판단하는 상태이며 별도 저장 필드가 아니어도 됨)
  - 참고: 원 요구사항은 "예정/진행/종료 상태를 관리함"이라 하여 관리자가 상태를 직접 관리하는 것으로도 읽히나, 본 문서는 구현 최소화를 위해 신청 시작일/종료일과 현재 날짜를 비교해 자동으로 판단하는 것으로 정의함

### 신청 (Application)
- 특정 샘플에 대한 특정 거래처 담당자의 신청 1건을 나타냄
- 상태: 신청(APPLIED) / 취소(CANCELLED)
- (샘플, 거래처) 조합당 신청 레코드는 유일하게 하나만 존재함

## 4. 주요 유스케이스(시나리오)

1. **관리자 - 샘플 등록/수정**: 관리자가 샘플명, 설명, 이미지, 신청 시작일/종료일을 입력해 샘플을 등록하거나 기존 샘플 정보를 수정한다.
2. **관리자 - 신청 현황 조회**: 관리자가 특정 샘플을 선택해 해당 샘플을 신청한 거래처 목록과 상태(신청/취소)를 조회한다.
3. **거래처 담당자 - 회원가입/로그인**: 거래처 담당자가 자가 회원가입 후 로그인한다.
4. **거래처 담당자 - 샘플 목록/상세 조회**: 로그인한 담당자가 신청 예정 또는 신청 가능한 샘플 목록과 각 샘플의 상세 정보를 조회한다.
5. **거래처 담당자 - 샘플 신청**: 담당자가 신청 가능한 샘플에 대해 신청 버튼을 눌러 신청을 등록한다.
6. **거래처 담당자 - 내 신청 내역 조회**: 담당자가 자신이 신청한 샘플 목록과 각 신청의 상태(신청/취소)를 조회한다.
7. **거래처 담당자 - 신청 취소**: 담당자가 신청 상태인 샘플을 취소한다(신청 기간 내라면 이후 재신청 가능).
8. **공통 - 마이페이지**: 관리자·거래처 담당자 모두 내 정보를 조회/수정하고 비밀번호를 변경한다.
9. **공통 - 로그아웃**: 로그인한 사용자가 로그아웃하면 인증 상태가 초기화되고 로그인 화면으로 이동한다.

## 5. 예외 케이스

- **중복 신청**: 동일 거래처가 이미 '신청' 상태인 동일 샘플에 다시 신청을 시도하면 신규 신청을 생성하지 않고 "이미 신청한 샘플입니다."를 안내한다.
- **신청 시작 전 신청 시도**: 샘플의 신청 시작일이 아직 되지 않은 경우(신청 예정 상태), 목록·상세 조회는 가능하나 신청은 허용하지 않는다.
- **신청 기간 종료 후 신청/재신청**: 샘플의 신청 종료일 다음 날부터는(즉 종료일 당일까지는 신청 가능), 신규 신청 및 취소 후 재신청을 모두 허용하지 않는다.
- **로그인하지 않은 접근**: 인증되지 않은 사용자는 어떤 기능도 이용할 수 없으며 로그인 화면으로 이동한다.

## 6. 비즈니스 규칙

- "샘플 신청"은 (샘플, 거래처) 조합당 유일하다. 동일 조합에 대해 신청 레코드는 항상 하나만 존재한다.
- 이미 '신청' 상태인 (샘플, 거래처) 조합에 대한 재신청 요청은 새 레코드를 만들지 않고 "이미 신청한 샘플입니다."를 안내한다.
- 신청 취소는 레코드를 삭제하거나 새 레코드를 만들지 않고, 기존 신청 레코드의 상태를 '신청 → 취소'로 변경한다.
- 취소한 샘플을 다시 신청하는 경우에도 새 레코드를 만들지 않고, 기존 신청 레코드의 상태를 '취소 → 신청'으로 되돌린다.
- 신청 시작일 이전에는 신규 신청을 허용하지 않는다(조회만 가능).
- 신청 종료일 당일까지는 신청·재신청이 가능하며, 종료일 다음 날부터는 신규 신청과 재신청(취소→신청 전환) 모두 허용하지 않는다.
- 모든 기능은 로그인(인증)한 사용자만 이용할 수 있다.

## 6-1. 부가 기능: 일일 신청 가능 개수 룰렛 (원 요구사항 범위 밖)

> 이 절은 사용자의 별도 요청으로 사후에 추가된 기능이며, 1~5절에서 정의한 원 도메인(샘플 신청 유일성, 기간 판정 등)과는 무관하다. 백엔드/DB는 변경하지 않고 프론트엔드에서만 동작한다.

- 거래처 담당자가 로그인하면(하루 최초 1회) 1~3 중 하나의 숫자가 무작위로 정해지는 룰렛이 뜨고, 사용자가 STOP을 눌러 결과를 확인한다.
- 그날은 뽑힌 숫자만큼만 샘플을 신청(재신청 포함)할 수 있다. 초과 시도는 화면에서 신청 버튼을 숨기거나 비활성화하는 방식으로만 막는다(서버 측 검증 없음).
- 같은 사용자가 같은 날 다시 로그인해도 이미 뽑은 결과가 유지되며 재추첨하지 않는다(날짜가 바뀌면 다음 날 다시 추첨).
- 신청 취소는 남은 개수를 되돌려주지 않는다(취소→재신청을 반복해 개수 제한을 무력화하는 것을 막기 위함).

## 7. MVP 범위 (포함/제외)

**포함**
- 관리자의 샘플 등록·수정 및 신청 현황 조회
- 거래처 담당자의 회원가입/로그인
- 거래처 담당자의 샘플 조회·신청·취소·신청 내역 조회
- 관리자·거래처 담당자 공통 마이페이지(내 정보 조회/수정, 비밀번호 변경)
- 모바일/데스크탑 대응 반응형 UI

**제외**
- 실제 상품 주문/결제/정산
- 배송 관리
- 실시간 재고 연동
- 샘플 재고 및 신청 가능 수량 관리 (참고: 6-1절의 "일일 신청 가능 개수 룰렛"은 샘플별 재고가 아니라 사용자별 하루 신청 횟수를 프론트엔드에서만 제한하는 별개의 부가 기능이다)
- 신청 승인 워크플로우
- 거래처 등급별 신청 조건 및 차등가
- 포인트/리워드
- 검색 기능
- 외부 시스템 연동

## 8. 용어집

| 용어 | 설명 |
|---|---|
| 샘플(Sample) | 거래처에 제공 가능한 상품 샘플. 신청 기간이 있음 |
| 신청(Application) | 거래처 담당자가 특정 샘플에 대해 등록한 신청 건 |
| 신청 상태 | 신청(APPLIED) 또는 취소(CANCELLED) |
| 거래처(Buyer) | 식자재를 구매하는 외식업체·급식업체 등 B2B 고객사 |
| 신청 기간 | 샘플의 신청 시작일부터 신청 종료일까지의 기간 |
| 일일 신청 가능 개수(룰렛) | 거래처 담당자가 하루 최초 로그인 시 뽑는 1~3 사이의 숫자로, 그날 신청 가능한 최대 횟수를 뜻함(6-1절, 프론트엔드 전용 부가 기능) |
